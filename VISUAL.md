# Visual Policy Workflow (Workbench)

This guide explains how to use the Workbench-integrated visual policy flow for AIC runs.

## What Workbench Sets

When you launch Workbench via `./workbench-ui` (generated by `RUN_ONCE.sh`), it now sets:

- `AIC_VISION_CAPTURE_DIR` (default: `/ws_aic/src/aic_policy_capture`)
- `AIC_VISION_MODEL_ENABLE` (default: `0`)
- `AIC_VISION_MODEL_PATH` (default: `/ws_aic/src/aic_policy/data/models/vision_offset_model.npz`)

So capture is available by default, and model inference is opt-in.

## Typical Flow

1. Launch Workbench:

```bash
./workbench-ui
```

2. Run Play or Eval once from UI to collect capture data.

3. In `AIC-Submission`, convert captured logs:

```bash
python3 scripts/make_labeled_npz.py \
  --jsonl /ws_aic/src/aic_policy_capture/capture.jsonl \
  --out-dir data/vision_labeled
```

4. Train model:

```bash
python3 scripts/train_vision_model.py \
  --data-dir data/vision_labeled \
  --out data/models/vision_offset_model.npz
```

5. Enable model for next Workbench run:

```bash
export AIC_VISION_MODEL_ENABLE=1
export AIC_VISION_MODEL_PATH=/ws_aic/src/aic_policy/data/models/vision_offset_model.npz
./workbench-ui
```

6. Run Eval in UI and compare behavior/scores vs baseline.

## Baseline vs Model A/B

- Baseline: `AIC_VISION_MODEL_ENABLE=0`
- Model: `AIC_VISION_MODEL_ENABLE=1`

Run both and compare trial outcomes and total score.

## Quick Checks

- No capture files:
  - Verify run was started via `./workbench-ui`
  - Check `/ws_aic/src/aic_policy_capture`

- Model not affecting behavior:
  - Confirm model file exists at `AIC_VISION_MODEL_PATH`
  - Confirm `AIC_VISION_MODEL_ENABLE=1` is in the environment used to launch Workbench
  - Re-run eval and inspect run output logs for policy startup/inference lines

## Notes

- This flow is designed to stay within contest constraints: camera-observation-based policy behavior, no ground-truth TF dependency in eval.
- External dataset disclosure/licensing notes are tracked in `AIC-Submission/notes/DATASETS.md`.
